# AI-Assisted Investigation Summary: Incident 001

## Executive Summary

Wazuh generated an alert for nested PowerShell execution on endpoint `WIN11-SOC-ENDPOINT`. The alert was triggered by Sysmon Event ID 1 and matched Wazuh rule `92027`, `Powershell process spawned powershell instance`. The command line included `-NoProfile` and `-ExecutionPolicy Bypass`, which are commonly reviewed by SOC analysts because they can be used to run PowerShell commands with reduced local policy friction.

This event was generated intentionally as part of a SOC lab validation exercise. Based on the reviewed evidence, there is no confirmed compromise. Surrounding Wazuh documents showed routine Windows activity and did not reveal obvious follow-on attacker behavior.

## Key Evidence

- Endpoint: `WIN11-SOC-ENDPOINT`
- Wazuh agent ID: `001`
- Wazuh rule: `92027`
- Rule description: `Powershell process spawned powershell instance`
- Rule level: `4`
- Sysmon event ID: `1`
- Event channel: `Microsoft-Windows-Sysmon/Operational`
- Command line:

```text
"C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -Command "Write-Output 'WAZUH-POWERSHELL-TEST-002'; whoami; hostname"
```

## MITRE ATT&CK Mapping

- Technique: `T1059.001 - Command and Scripting Interpreter: PowerShell`
- Tactic: `Execution`

This mapping is appropriate because PowerShell was used to execute commands on the endpoint. The mapping does not prove malicious intent by itself.

## Recommended Response Plan

If this were a production alert, the analyst should:

1. Confirm the user and host context for the PowerShell execution.
2. Review parent and child process relationships from Sysmon Event ID 1.
3. Check PowerShell Script Block Logging for command content.
4. Review surrounding events for downloads, persistence, account changes, credential access, or network connections.
5. Validate whether the command was part of approved administrative activity.
6. Escalate or contain the endpoint only if additional suspicious evidence is identified.

## Open Questions

- Was the PowerShell command expected or approved?
- Were there any related network connections after the process creation?
- Were any files written, deleted, or downloaded by the PowerShell session?
- Did the same user or host trigger similar alerts before or after this event?
